RelaGrid は、MySQL のスキーマを可視化し、テーブル関係とデータの流れを探索できる Windows デスクトップアプリです。

Tauri + React + TypeScript + React Flow + shadcn/ui を採用し、リレーションの確認とSQLの実行を別画面で行えます。接続時に「読み取り専用」を選択できます（既定はオン）。

## 技術スタック

- 言語:
  - TypeScript `~5.7.3`

  - React `19.0.0`
  - Vite `6.4.0`

  - Windows 11 / Windows 10 向けデスクトップアプリ
  - WebView2 依存
  - MySQL 8.0 を対象とした接続ごとの読み取り／読み書きアクセス

## 起動

WindowsではNode.js 20以上、Rustup、Visual StudioのC++ビルドツール、WebView2が必要です。Rustは `rust-toolchain.toml` のバージョンを使用します。

```powershell
npm install
npm run dev
```

この1コマンドで画面の開発サーバーとTauriをまとめて起動します。バックエンド用サーバーの管理は不要です。初回はRustの依存ライブラリのダウンロードとコンパイルに時間がかかります。MySQLサーバーは別サービスとして稼働している必要があります。

起動時は未接続です。「接続を追加」からホスト（既定 `127.0.0.1`）、ポート（既定 `3306`）、DB名、ユーザー名、パスワードを入力してください。接続成功後に接続先・グループ・読み取りモードを自動保存し、次回起動時に接続一覧を復元します。復元後は一覧から接続先を選択して接続します。サンプルDBや内蔵デモへの接続はありません。

設定はWindowsのアプリ設定フォルダー `%APPDATA%\com.relagrid.desktop\connections.json` に保存します。パスワードはAES-256-GCMで暗号化し、256ビットの乱数鍵をWindows DPAPI（現在のユーザー）で保護します。保存ごとに新しい鍵、パスワードごとに新しい96ビットnonceを生成します。JSONの `protectedKey` はDPAPI保護済み鍵、各 `config.password` はnonce＋暗号文＋認証タグのBase64です。ホスト、ユーザー名、DB名などはJSONで確認できますが、認証対象なので直接編集せずアプリで設定してください。グループの追加・移動も保存します。切断しても保存済み接続は残ります。

保存は同じフォルダーの一時ファイルを経由して置き換えます。一時ファイルにも平文パスワードは書きません。復号・読み込みに失敗した設定は上書きせず、エラーを表示します。別のWindowsユーザーや端末へのJSONコピーだけでは通常復号できません。非Windows環境では安全でない代替保存を行わずエラーにします。暗号化処理は [RustCrypto AES-GCM](https://docs.rs/aes-gcm/0.10.3/aes_gcm/)、鍵保護は [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) を使用します。

接続画面の「接続ファイルを読み込む（JSON）」では、従来形式の外部ファイルも入力できます。`connections/mysql.example.json` を参考にしてください。必須項目は `host`、`port`（整数）、`database`、`username`。`password` は省略時に空文字、`readOnly` は省略時に `true`、`group` は任意です。外部ファイル自体は書き換えないため、平文パスワードを含むインポート元は別途削除・管理してください。自動保存先の暗号化JSONはこのインポート形式とは異なります。

React・ViteはTauri内の画面を構築するために使用します。`dev:ui` はTauriと画面テストが内部で呼び出す開発サーバー用コマンドです。通常の開発では `npm run dev`、アプリ全体のビルドでは `npm run build:desktop` を使用してください。`npm run build` はアプリに組み込む画面部分を生成する内部工程です。ブラウザ版の配布は対象にしていません。

## MySQLのTLS設定

すべてのMySQL接続でTLS、信頼するCAによる証明書検証、ホスト名検証を必須にしています。非TLS・自己署名で未信頼の証明書・期限切れ・ホスト名不一致の場合は接続を拒否し、検証なしへフォールバックしません。既存の保存済み接続にも適用するため、これまで接続できたサーバーでも証明書設定の修正が必要な場合があります。

社内CAの場合は接続画面の「信頼するCA証明書」にPEM証明書を入力してください。JSONインポートでは任意の `tlsCaPem` にPEM文字列を指定できます（最大64KB、秘密鍵は不可）。未指定の場合はSQLx/rustlsの組み込みの信頼済みCAを使います。接続ホストはサーバー証明書のSANと一致させてください。IPアドレスで接続する場合は、そのIPのSANが必要です。

CA設定も暗号化パスワードの認証対象に含め、接続保存形式をv2へ更新しています。v1はCA設定なしとして復号でき、次回保存でv2になります。v1に後付けされた未認証のCA設定は拒否します。

## 実装済み

- 接続先DBのベーステーブル、カラム、主キー、外部キーの取得
- カラム単位の関係図、ドラッグ、ズーム、ミニマップ、自動配置
- テーブル名・カラム名でのサイドバー検索、詳細表示、関連テーブルの強調
- 選択テーブルのプレビュー（先頭100件、各値最大500文字）
- 取得済みプレビューをテーブルごとにメモリ内で保持し、再選択時に復元
- スキーマ更新、接続切り替え・切断、アクティビティログ

リレーション画面にはアクティビティとテーブルのデータプレビューを表示します。SQL画面にはクエリタブ、SQL入力、結果・実行計画・メッセージ、クエリ詳細と実行履歴を表示します。画面の切り替えでSQL入力と実行結果は保持されます。Ctrl+Nで新規クエリ、Ctrl+Sでアクティブなクエリを保存、Ctrl+Shift+Sですべてのクエリを保存します。Ctrl+Wで閉じる際、未保存の変更があれば破棄の確認を表示します。取得結果のCSV出力にも対応します。

接続ダイアログの「読み取り専用」を外すと、DBユーザーの権限の範囲で更新SQLも実行できます。設定は現在の接続に保持し、接続に失敗した場合は以前の接続と設定を維持します。現在は接続先を1つずつ切り替える構成で、接続情報は暗号化保存します。クエリタブには作成時の接続先を保持し、接続切り替え・切断後もSQLと取得済み結果をメモリ内に残します。接続を切り替えると、その接続の既存タブ（なければ新規タブ）を選択します。別接続のタブは閲覧・編集できますが、実行にはサイドバーで元の接続を選ぶ必要があります。履歴からの再作成も元の接続先を保持します。保存したクエリ名・SQL・接続先はアプリ設定フォルダーの queries.json に出力し、次回起動時に再び開きます。閉じた保存済みクエリもファイルに保持されます。未保存の変更と実行結果は復元しません。保存に失敗した場合は未保存状態を維持します。ファイル保存はデスクトップ版で利用できます。接続・スキーマ更新時にはテーブル件数（推定件数を含む）を取得しません。

SQL実行は全タブを通じて1件ずつです。実行中もタブやSQL／リレーション画面を切り替えられ、結果とエラーは実行元のタブに戻ります。結果の表示種別・ページ・表示行数もタブ別に保持します。実行中タブは閉じられません。「中断」で処理の終了を待ってから閉じてください。中断はクライアント側の実行接続を解放するもので、サーバー側の即時停止や更新のロールバックを保証しません。更新SQLの反映状況は確認してから再実行してください。

タブの `*` はファイル出力したSQLからの変更（新規SQLを含む）を示し、未保存SQLを閉じる際は破棄を確認します。「保存する」はSQLファイルのダウンロードを開始します。OS側の保存完了を検知するものではありません。最後の1タブは既存仕様どおり残します。調査・検証結果は [RG-00 / RG-01 メモ](docs/rg-00-01.md) を参照してください。

読み取り専用では各SQL文の構文を解析してSELECT系以外・SELECT INTO・実行可能コメントを拒否し、MySQLセッションにも読み取り専用を設定します。MySQL接続では最大20文のSELECT・INSERT・UPDATE・DELETEをまとめて実行できます（更新文は読み書き可能な接続のみ）。SQLは自動コミットで、複数文全体の原子性はありません。列情報と各文の構文を事前確認してから元のSQL全体を送信するため、DDLと実行計画は1文ずつ実行してください。セッション変更、明示的なトランザクション操作、CALLは未対応です。実行計画はSELECTに対するEXPLAINです。SQLの構文はMySQL向けパーサーが対応する範囲に限ります。

複数結果は「結果 1」「結果 2」などのタブで切り替え、更新件数は「更新」タブに表示します。空の結果も列を表示し、ページ・スクロール位置・選択中の結果をエディタ別に保持します。途中失敗では取得済み結果を残し、実行全体の失敗と未完了の結果を明示します。再実行で古い結果を破棄します。

SQL結果の保持上限は結果ごとに1,000行、各値5,000文字（バイナリは最大2,500バイトを16進表示）、実行全体で約5MBです。上限で省略した場合は画面に表示します。後続結果を受け取るため、省略した行も保存せず読み進めます。CSVは選択中の表形式結果の取得済み行だけを出力します。SELECTのサーバー側制限は5秒、SQLの事前確認・実行・取得の待機上限は全体で15秒です。タイムアウト時、更新SQLの反映状況は別途確認が必要です。実行ごとにSQL専用の接続を破棄し、セッション状態がプレビュー処理へ残るのを防ぎます。対応範囲と検証は [RG-02 メモ](docs/rg-02.md) を参照してください。

リレーションのプレビューは先頭100件・各値500文字までです。

## キーボード操作

| 操作                       | キー                      | 有効な場所                              |
| -------------------------- | ------------------------- | --------------------------------------- |
| 新規エディタ / 終了        | Ctrl+T / Ctrl+W           | SQL画面のエディタ・結果・詳細           |
| 次 / 前のエディタ          | Ctrl+Tab / Ctrl+Shift+Tab | 同上                                    |
| SQL全文を実行              | F5 / Ctrl+Enter           | 同上。選択範囲があっても全文を実行      |
| 現在のエディタの実行を中断 | Shift+F5                  | 同上。別タブの実行は中断しない          |
| SQL / リレーション切り替え | Ctrl+Shift+M              | 入力欄・ダイアログ以外（SQL入力は有効） |
| 次 / 前の結果              | Alt+→ / Alt+←             | 結果領域にフォーカスがあるときのみ      |

ボタンとキーは同じ操作を呼び、実行できない状態・実行中タブの終了・最後のタブ・未保存SQLの確認も共通です。エディタの追加・移動後はSQL入力へフォーカスを戻します。結果領域はTabキーでフォーカスできます。IME変換中、検索や接続設定などの入力欄、ダイアログでは上記コマンドを動かしません。キー長押しによる連続操作も抑止します。

既存のTab補完・Ctrl+Space候補表示・入力欄外の`/`検索は維持します。割り当てはボタン・クエリタブ列・結果領域・画面切り替えのツールチップでも確認できます。検証範囲は [RG-03 メモ](docs/rg-03.md) を参照してください。

## 構成と拡張

プレビューを取得したテーブルは、別のテーブルへ移動して戻っても再取得せず表示します。「データを表示」を再度押すと最新データを取得し直します。保持データは接続切り替え・切断・スキーマ更新の成功時に破棄し、アプリ終了後には残りません。接続や更新が失敗した場合は以前の保持データを維持します。

```text
src/
  app/                  画面全体の組み立て
  domain/               DBに依存しないデータ型・Gateway契約
  data/                 Tauri通信と接続設定の保存
  features/
    connection/         接続フォーム
    explorer/           探索状態・サイドバー・詳細・プレビュー
    graph/              関係図・ノード・自動配置
    query/              SQLエディタ・実行結果・クエリ詳細と履歴
  components/ui/        shadcn/uiの構成に沿った共通部品（Radixベース）
  lib/                  共通ユーティリティ
  styles/               画面領域別のスタイル
src-tauri/src/
  lib.rs                Tauriコマンド・接続セッション管理
  models.rs             IPCのデータ型
  database/mysql.rs     MySQL固有のメタデータ取得・プレビュー
  database/mysql_sql.rs SQL定義・安全なプレビューSQLの組み立て
```

画面は `DatabaseGateway` に依存します。テスト用のデータは `tests/fixtures` に分離しています。新しいDBを追加する場合はRust側のアダプターと接続設定を追加し、共通の `SchemaSnapshot` / `Preview` を返すようにします。Rust側でDB種別が2つ以上になる時点で共通トレイトを導入する想定です。現段階では不要な汎用化を避けています。

プレビュー要求には世代番号を持たせ、テーブル変更・接続変更後に古い結果が表示されるのを防ぎます。接続・更新・切断は同時実行を防ぎます。接続変更は、新しい接続とスキーマの取得に成功した時点で置き換えるため、失敗しても以前の接続は維持されます。

`components.json` でshadcn/uiの追加先・テーマを設定しています。UI部品はプロジェクト内で所有し、画面固有のスタイルと分離しています。TypeScriptのstrictモード、Prettier、Rustfmtを使用します。

## 保存SQLの保護と削除

`%APPDATA%\com.relagrid.desktop\queries.json` は、SQL本文・クエリ名・接続先を含めてWindows DPAPI（現在のユーザー）で暗号化・改ざん検出します。従来の平文配列は、読み込み・検証に成功した後、暗号化済みの一時ファイルを経由して自動移行します。平文のバックアップは作成しません。復号・移行・保存に失敗した場合は元ファイルを保持してエラーにし、保存を停止します。非Windows環境では平文保存にフォールバックしません。

SQLにパスワードやトークン、不要な個人情報を埋め込まないでください。この保護は保存ファイルが対象であり、同じWindowsユーザーの権限で動く悪意あるプロセス、メモリ内のSQL、コピー済みの旧ファイルや外部バックアップを保護するものではありません。移行はストレージ上の旧データの安全消去を保証しません。

保存クエリをすべて削除するには、RelaGridを終了してから上記の `queries.json` を削除してください。次回起動時は保存クエリなしで開始します。接続設定の `connections.json` は削除不要です。クエリタブを閉じるだけでは保存済みクエリは削除されません。

## CSVの保存形式

現在の画面のCSV出力は、UTF-8 BOM付き・カンマ区切り・ヘッダーあり・CRLF区切りです。選択中の取得済み行だけを列順どおりに出力します。NULLは空文字になり、数式として解釈されうる値にはアポストロフィを付けます。

エクスポート画面で対象件数・列数と省略の有無を確認できます。デスクトップ版では保存先を選び、進捗表示を見ながら書き出しを中断できます。同じフォルダーの一時ファイルへ分割して書き込み、完了時に保存先へ確定します。SQLの再実行や全件取得は行いません。ブラウザの画面テストはダウンロードのみで、ディスク保存の完了は確認できません。[RG-05 メモ](docs/rg-05.md) に検証範囲と残る作業を記載しています。

MySQL接続時は、リレーション画面のデータプレビューから「テーブル全件をCSV出力」を選べます。この操作は選択テーブルを新たに読み取り、表示上限を適用せず順次保存します。任意のSQLエディタ内容は実行しません。進捗・中断に対応し、10分・512列・値サイズ上限を超えた場合は完成ファイルを確定しません。TIMESTAMPはUTC、バイナリは16進表現です。詳しい上限と検証は [全件出力メモ](docs/rg-05-stream.md) を参照してください。

全件CSV出力は画面を開いた接続に紐づきます。接続の切り替え中は開始できず、切り替え・再接続時は古い出力画面を閉じます。保存先選択後と読み取り開始前にもバックエンドで接続を照合するため、別の接続に同じDB名・テーブル名があっても出力を引き継ぎません。確認画面のホスト・ポート・DB名を確認してから開始してください。

型・精度・NULLを保持する往復形式v1の共通処理を追加しました。これはまだ画面の保存・取り込みには接続していません。対応型、NULLトークンのエスケープ、上限と検証範囲は [RG-04 メモ](docs/rg-04.md) を参照してください。

## 検証

```powershell
npm run build
npm test
npm run test:e2e
npm run format:check
cargo test --manifest-path src-tauri/Cargo.toml
npm run check:rust
```

画面のE2Eは、デスクトップ版と共通のReact画面をインストール済みのMicrosoft Edge上で検証します。ブラウザ版製品のためではなく、画面の回帰テスト用です。レイアウト・循環参照・関連ノードの単体テストと、検索・選択・プレビュー・接続エラーの操作テストがあります。実際のTauri通信の検証は `tests/native-smoke.mjs` が担当します。

MySQL統合テストは通常スキップします。**検証用の独立したMySQL**を `127.0.0.1:3307` に立て、`tests/fixtures/schema.sql` を投入してから実行してください。ユーザーは `root`、空パスワード、DBは `relagrid_fixture` です。既存の業務DBには投入しないでください。

```powershell
cargo test --manifest-path src-tauri/Cargo.toml mysql_fixture -- --ignored --test-threads=1
```

このテストはスキーマ・外部キー・日本語・NULL・数値・バイナリの読み取りと、読み取り専用セッションがUPDATEを拒否することを確認します。

実MySQLの統合テストにもTLS検証を適用します。検証サーバーに127.0.0.1のSANを持つ証明書を設定し、必要に応じて環境変数 `RELAGRID_TEST_CA_PEM` に検証用CAのPEM本文を指定してください。GUIのネイティブ試験は接続画面にもCAを指定する必要があります。通常のRustテストには、外部DBを使わずループバックのMySQLハンドシェイクで正しいCA・未信頼CA・期限切れ・ホスト名不一致・非TLSを検証する試験を含みます。`src-tauri/test-fixtures/tls` の鍵は公開された試験専用鍵で、本番に使用してはいけません。

全件CSVテストが一時テーブルを作成するため、同じfixtureを使う統合テストは直列で実行します。追加した異常系・境界値テスト、隔離プロファイルでのデスクトップ起動テスト、未検証項目は [QA検証記録](docs/qa-coverage.md) を参照してください。

## 初期版の範囲

- 対応DBはMySQL 8.0。初回に指定した1つのDBを表示します。
- 行数はMySQLの推定値です。外部キーのない関係は推測しません。
- DBをまたぐ外部キー、ビュー、インデックス詳細は未対応です。
- 複合外部キーはカラムごとに表示します。線の `FK` は外部キーを意味します。UNIQUE制約やNULL許可による厳密な多重度は判定しません。
- 大規模スキーマの仮想化、レイアウト永続化、データ編集、INSERT生成、依存データのコピー、環境間同期は未実装です。
- 自動配置は軽量な階層配置です。循環参照のある図の最適化は今後ELKなどへ差し替えられます。
- バイナリは16進文字列で表示します。プレビューは全文・全件エクスポートではありません。
