# SQL閲覧の資源制限

表示する結果の保持量とDBからの取得量を別々に制限します。

| 対象           | 上限・動作                                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| 表示保持       | 結果ごとに1,000行、値5,000文字（バイナリ2,500バイト）、実行全体で約5MB                                            |
| 閲覧SELECT取得 | 純粋なSELECTの実行接続に `sql_select_limit=1001` を設定。1,001行目は省略の検出用。受信時にも1,001行目で接続を破棄 |
| 累積取得値     | 全結果のセルの生バイト数を合計し20,000,000バイトを超えた時点で接続を破棄                                          |
| ドライバー受信 | MySQLパケットのヘッダー長が8,000,000バイトを超えたら、ペイロードを読み込む前に拒否                                |
| メタデータ     | 512列、保持する列名は各4,096バイト。未検証の列数による巨大な事前割当を拒否                                        |
| 時間           | SQLの事前確認・制限設定・実行・取得は15秒、接続側SELECT時間制限は別途5秒                                          |

SQL末尾にLIMITを付けたり、SQLを派生表で包んだりしません。MySQLのセッション上限は明示LIMIT等で適用されない場合があるため、受信行数も検査します。実行計画や書込みSQLには閲覧SELECTのセッション上限を設定しません。結果の省略を明示し、全件結果として扱いません。

SQLバッチは元の文字列を一括送信しています。取得上限や通信エラーで接続を破棄しても、後続文がサーバーで実行されていないとは保証できません。画面のエラーは「後続文の実行状態は不明」と表示します。完了応答を受け取っていない現在の結果も未完了扱いです。更新バッチはトランザクション対応まで拒否します。

セルはドライバーが保持するバイト列を借用し、表示用の短い文字列だけを作成します。セル全体の `Vec<u8>` コピーを作りません。ただし、受信パケット自体・TLSバッファ・列情報・結果保存・IPCの複製・アロケータ・並行接続もメモリを消費するため、上記はプロセス全体のピークメモリを8MBに制限する保証ではありません。累積20MBはセル値の合計であり、ヘッダーやメタデータを含む正確なネットワーク転送量ではありません。上限を超えた最後の1行は検査前にドライバーで受信済みです。

## ドライバーの保守

`src-tauri/vendor/sqlx-mysql` はSQLx 0.8.6のMIT/Apache-2.0ライセンス付きソースです。`Cargo.toml` のpatchで利用します。8MBの上限はMySQLの継続パケット境界16,777,215バイトより小さく、巨大な継続パケットの組立てに到達しません。パッチの詳細は同梱 `RELAGRID-PATCH.md` を参照してください。SQLx更新時はパッチとテストを移植します。

この受信ガードはSQL閲覧だけでなく、プレビュー・全件CSVを含む全MySQL接続に適用します。異常応答を受け取った接続は再利用前に正常性を確認し、SQL専用接続はそのまま破棄します。

## 全件CSVと運用

SQL結果のCSVは取得済み・表示保持済みの行だけを保存します。全件CSVは別のテーブル読み取り処理で、閲覧の1,000行制限を適用せずストリーミング保存します。全件CSV独自の時間・列数・値サイズ制限と8MBのドライバー受信制限が適用されます。エラー時は完成ファイルを確定しません。

大規模な閲覧や全件CSVは、本番の更新用DBから分離した参照用レプリカと専用の読み取りユーザーで行ってください。LIMITは結果転送を抑えてもJOIN・ソート・集計の計算量を保証しません。レプリカの遅延と利用者ごとの接続・クエリ制限も運用で管理します。

## 検証範囲

ドライバーの単体テストはパケット境界、継続パケット拒否、4バイトの異常ヘッダーだけを供給するソケットでのペイロード未読、巨大列数の拒否を検査します。アプリの単体テストはUTF-8・バイナリの表示切詰め、20MBの境界と加算オーバーフローを検査します。実DBでの大量行・巨大BLOB・受信量・ピークメモリの実測結果は別途記録します。単体テストだけで受け入れ条件の実測完了とは扱いません。

2026-10-06に専用ローカルTLS MySQL 26.7（製品対象のMySQL 8とは異なる）で、8,000,001バイトの巨大値のパケット拒否、22行×1MBの累積値取得の停止、停止後の別接続でのSELECT成功を確認しました。ドライバーの模擬ソケットでは異常応答ヘッダーの読み取りが4バイトだけで、ペイロード未読を確認しました。資源制限テストを単独プロセスで実行した際、WindowsのPeakWorkingSet64で観測したピークは17,944,576バイト（5ms間隔で観測、実行0.38秒）でした。これはテストプロセスの観測値で、デスクトップアプリ全体の上限や最悪条件の保証ではありません。実DBのネットワーク転送量の実測、アプリ全体のピークメモリ測定、およびMySQL 8での再検証は未完了です。
