# RG-05: MySQLテーブルの全件ストリーム出力

2026-09-25。取得済み結果のExport（`0a825c2`）に続く変更。Relation Viewの選択テーブルに対し、表示用の100行・500文字の上限を適用しない全件取得を追加した。SQLエディタの内容を再実行する機能ではない。

## 取得と保存

実MySQL接続のデータプレビューに「テーブル全件をCSV出力」を追加した。ダイアログに対象スキーマ・テーブル、列数、既存プレビューとは別に取得すること、形式・上限を表示する。総件数は推定値を使わず取得完了時に確定する。出力順は保証しない。

`export_table_csv`は現在の接続が保持するスキーマ情報からテーブルIDを解決し、カタログ由来の列・テーブル名をエスケープした単一SELECTを生成する。SQL本文や任意の識別子を直接受け取らない。処理中は接続状態をロックし、途中で別の接続に切り替わることを防ぐ。

プールから取得して切り離した接続を読み取り専用にし、セッション時差をUTCに固定する。日時文字列を端末のローカル日時へ変換しない。TIMESTAMPはUTC、DATETIMEは保存されたローカル表現のまま、バイナリ・BIT・地理型はHEXとなる。数値等はサーバーの文字列表現を使用する汎用CSVであり、型の完全往復は約束しない。NULLは空文字へ変換し、数式として解釈されうる先頭文字には既存と同じアポストロフィを付ける。

Rust側でsqlxの行ストリームを読み、`csv` crateのwriterへ1行ずつ渡す。フロントへ全行を送らず、全件分の配列・文字列を生成しない。CSVはUTF-8 BOM、ヘッダーあり、全フィールド引用、カンマ、CRLF。既存の取得済み結果と異なり、全件出力では最終レコードにもCRLFが付く。どちらもRG-04のreaderで扱えるCSV構文だが、型保持形式のメタデータは付けない。

既存の一時ファイル・同期・置き換え処理を再利用する。完了前に既存ファイルを変更せず、中断・サイズ超過・読取/書込失敗・タイムアウト時は完成品として確定しない。通常失敗時は一時ファイルを削除し、削除失敗も通知する。中断受信口は保存先の決定時に作成し、全件取得の開始前に届いた中断も見落とさない。取得のfutureを破棄してreaderと専用接続を解放する。最終確定処理に入った後は中断で取り消せない。

件数通知は100行ごとに時刻を確認し、最大およそ250msに1回＋完了時に送る。通知前にはwriterをflushする。高速取得で進捗メッセージが大量に蓄積することを抑える。中断確認の機会も100行ごとに作る。

## 上限と制約

- 行数の固定上限はない。取得開始から10分、1〜512列まで。
- 値のUTF-8/HEX表現上限は `min(1MiB, floor(8MiB / 列数))` バイト。画面にそのテーブルの上限を表示する。バイナリはHEX展開後のサイズで判定する。
- SQL側で各値を上限＋1バイトまで取得し、超過を検出したらレコード・列位置付きで拒否する。これにより受信する1行も約8MiB＋列数に制限する。切断位置がUTF-8の途中でも、サイズ超過として拒否してからデコードする。その他の不正UTF-8も拒否する。
- クライアントの追加メモリは1行・CSVのバッファ・進捗通知に依存し、全件数に比例しない。ドライバと文字列変換には追加コピーがあり、8MiBはプロセス全体の上限ではない。DBサーバー内部の変換・読み取り負荷は別途発生する。
- 出力は単一SELECTであり、複数テーブルの一貫したスナップショットや、同時DDL/非トランザクションテーブルの内容の固定を保証しない。任意のクエリ全件再実行、テーブル間の整合性保証、型メタデータ付き保存は未実装。
- ブラウザデモにはこの全件取得ボタンを出さない。全件出力中の接続変更・通常のDB操作は接続ロックの解放を待つ。強制終了時に残る`.partial`は未完成品。
