## テストとの照合方法

各詳細設計に正常系・異常系・境界値・権限差の観点と既存ファイル／テスト識別子を記載した。対象コミットのテストコードを根拠とし、「テストが存在する」と「今回実行して成功した」を区別する。

| 層                      | 役割・限界                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------ |
| Vitest                  | ロジック・React状態・模擬非同期／保存を確認。DBやDPAPIの実動作保証ではない                 |
| Rust通常テスト          | SQL生成／検証、ファイル保存、中断、TLS模擬ハンドシェイク。Windows条件付きDPAPIテストを含む |
| Playwright              | EdgeでUIとCodeMirror。DB／ファイルIPCを模擬するケースが多い                                |
| ignore付きMySQL fixture | 実DBのスキーマ・モード差・SQL結果・全件CSV。隔離合成データとTLS設定が必要                  |
| native smoke            | QA識別子の実Tauri／DB用。通常ユーザー設定や本番DBで実行しない                              |

通常のコマンドと過去の実行記録は[QA資料](qa-coverage.md)、環境前提は[README](../README.md)と[TLS fixture](../src-tauri/test-fixtures/tls/README.md)を参照する。
