# 本番DBへの接続権限

本番閲覧には対象スキーマだけを参照できる専用ユーザーを使用してください。接続画面でユーザー名の自動入力は行いません。ユーザー名がroot以外であっても、最小権限であるとは限りません。権限はDB管理者が確認してください。

## 機能と権限

| 用途                                      | 方針                                                                               |
| ----------------------------------------- | ---------------------------------------------------------------------------------- |
| スキーマ表示・プレビュー・SELECT・全件CSV | 対象スキーマへのSELECTを基本とする。見えるメタデータはそのユーザーの権限に従う     |
| データ修正                                | 閲覧アカウントと分離し、必要な対象へのINSERT・UPDATE・DELETEのみを個別に許可する   |
| DDL・ユーザー管理・サーバー管理           | 閲覧アカウントには許可しない                                                       |
| SQL中断                                   | 現行版はサーバー側停止の確認が未実装。これを目的にグローバルな管理権限を付与しない |

アプリの読み取り専用モードを、DB権限の代わりにしないでください。SELECT以外の権限（FILE、EXECUTE、権限委譲や管理権限等）は、閲覧目的では原則不要です。対象外スキーマへの参照も許可しないでください。

DB管理者は独立した検証DBで、専用ユーザーによるスキーマ表示・プレビュー・SELECTが成功し、UPDATEや対象外スキーマへのアクセスがDB側で拒否されることを確認してください。本番データを使った拒否テストは行わないでください。

## 現在の制約

本番環境を識別する専用設定と、管理者接続・書き込み有効化の追加確認は未実装です（Issue #8）。既存の保存済みアカウントの権限は変更しません。統合テストに記載したroot・空パスワードは隔離した検証用fixture専用であり、本番設定の例ではありません。
