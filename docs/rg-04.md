# RG-04: CSV構文と型・NULLの共通規約

2026-09-24。RG-03（`1c40fda`）に続く変更。CSV構文と型の検証を分離し、RG-05/06から再利用する共通処理を追加する。

## 既存実装と変更

`QueryWorkspace.tsx`の手書きCSV出力を`features/csv/csv.ts`へ移した。構文処理には`csv-parse` 7.0.2 / `csv-stringify` 6.8.3のブラウザ用同期APIを使用する。依存はこの2つだけ追加した。

既存画面の「CSV」は選択中の取得済み結果だけを出力する汎用CSV。NULLは空文字へ変換し、数式として解釈されうる先頭文字には従来どおりアポストロフィを付ける。通常のシングルクォートはそのまま保存する。出力はUTF-8 BOM付き、カンマ区切り、ヘッダーあり、全セルを二重引用符で囲み、引用符を二重化する。レコード間はCRLF、末尾改行なし、列順は結果の配列順。

型付き往復保存は`round-trip.ts`の共通APIとして追加した。現時点のクエリ結果には信頼できる型・精度情報がなく、値の省略もありうるため、画面から型付き保存を選ぶ機能はまだ提供しない。DB型マッピングと省略検出、ファイル入出力はRG-05/06で接続する。今回SQL生成・DBへの書き込みは追加していない。

## 往復形式v1

`encodeRoundTrip(columns, rows)`はCSV文字列とJSON化可能なメタデータを返す。`decodeRoundTrip(csv, metadata)`は型を検証して文字列/NULLの配列を返す。数値への暗黙変換や時刻のローカル変換はしない。

```json
{
  "format": "relagrid-csv",
  "version": 1,
  "encoding": "utf-8",
  "bom": true,
  "delimiter": ",",
  "header": true,
  "newline": "CRLF",
  "nullEncoding": "backslash-v1",
  "rowCount": 1,
  "columns": [
    { "name": "id", "nullable": false, "type": { "kind": "integer", "bits": 64, "signed": true } }
  ]
}
```

CSV構文を解いた後のセルで、NULLは`\N`（バックスラッシュ1つ）。非NULL文字列がバックスラッシュで始まる場合は先頭にもう1つ付ける。したがって文字列`\N`は`\\N`になり、空文字・空白・`NULL`とはすべて区別できる。それ以外の先頭バックスラッシュ表現は取り込み時に拒否する。型付き形式では数式対策の文字追加を行わず、元の文字列を保持する。

メタデータのバージョン・形式・列型・範囲を実行時に検証する。ヘッダー名と順番、列数、データ行数を照合する。同名列は位置で区別する。行数照合は完全性認証ではない。読取構文はBOMなしとLF区切りも許容し、引用内の改行は変更しない。

| 型             | 対応範囲・表現                                                                                                    |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| text           | Unicode。任意の最大文字数はコードポイント単位。不正なサロゲートは拒否                                             |
| integer        | 符号あり/なし8・16・32・64ビット。BigIntで範囲を検証。指数・小数・先頭ゼロは拒否                                  |
| decimal        | 精度1〜65、スケール0〜精度。固定小数文字列。桁あふれを拒否し、丸め・ゼロ埋めをしない。末尾ゼロを保持              |
| boolean        | `true` / `false`のみ                                                                                              |
| date           | `YYYY-MM-DD`、西暦0001〜9999、閏日を検証                                                                          |
| datetime       | `YYYY-MM-DDTHH:mm:ss[.fraction]`、小数秒0〜7桁。オフセットなし                                                    |
| datetimeOffset | datetimeに`Z`または`±HH:MM`必須。最大±14:00。指定した小数秒上限を超える値は拒否し、オフセットと桁数をそのまま保持 |
| binary         | 接頭辞なしの偶数桁16進文字列。大文字/小文字を保持、任意の最大バイト数を検証                                       |

浮動小数・JSON・地理型など、表にない型は拒否する。これは共通保存形式の対応表であり、すべての型がMySQLで対応済みという意味ではない。DBへの変換可否やMySQL固有の日時範囲は後続のアダプターで検証する。

## 上限とエラー

現APIは小規模ファイル向け同期処理。読取はUTF-8で32MiB、パーサのレコードサイズ上限8MiB、ヘッダーを除く10,000行、4,096列まで。行・列上限はパース途中でも確認する。型付き出力は同じ上限を満たすことを読取処理で再検証する。全件ストリーミング処理は未実装であり、大容量Export/Importの完了を意味しない。

バイト列は`decodeCsvUtf8`で厳密にUTF-8として読み、不正なバイトを置換しない。CSV構文エラー、型不一致、NULL禁止などは1始まりの論理レコード・列番号で返す。ヘッダーはレコード1。ライブラリのエラー本文に含まれる可能性のあるセル値は公開しない。未知のメタデータ形式は処理開始前に拒否する。
